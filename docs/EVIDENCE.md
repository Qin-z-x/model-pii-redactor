## Scope and honesty statement

`model-pii-redactor` is a defensive redaction tool. It does not disclose a new vulnerability, does not claim a new CVE and does not make an output pipeline compliant with any privacy regulation. The PII in the examples is synthetic. Pattern matching can miss formatted or unexpected identifiers and can flag benign strings; the report mode exists so an operator can review before redaction.

## Limitations

- Detection is regex + checksum based: unusual formats, non-Latin identifiers and context-dependent PII
  can be missed; names and addresses are out of scope.
- A Luhn-valid number is only a candidate card number, not proof of a live card.
- The report JSON deliberately masks values; if you need the raw span, use the library API in-process and
  handle the result as personal data.
- Hash mode is a deterministic pseudonym, not anonymisation: an attacker who knows the salt can brute
  force common values. Keep the salt secret and rotate it per deployment if needed.
- Redaction happens where you call it. Model output stored elsewhere (vendor logs, PI traces) is not
  covered; apply redaction at ingestion and egress.
